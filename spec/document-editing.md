# Shared-document editing

An editor operates on immutable UTF-8 document bytes (or absence), explicit
section/structured requests, the complete current ownership set and resource
creation provenance. It returns the complete original and proposed document,
proposed ownership, provenance and per-request observations. It performs no I/O.
The caller assigns bundle/artifact attribution and persists these records under
its resource authority. Artifact renames keep the same physical claim and baseline.

A request either sets one closed section/structured content or retires its claim.
Existing claims omitted from the requests remain owned. Requests and existing
claims must be unique and nonoverlapping. One resource uses one document format.
The editor rejects malformed documents, ambiguous selectors and incompatible
claim sets. It reports acquisition conflicts, modified units and unsafe restoration
without publishing a partial proposal: one blocked request preserves the complete
original document, ownership and provenance. Successful observations in such a
result describe preflight proposals, not committed changes.

Whole-document before/after snapshots are publication and preview preconditions.
They do not authorize selective recovery after an unexpected revision; the
[transaction contract](configuration-state.md) requires recognized complete
revisions for rollback.

## Acquisition and retirement

A preexisting unowned selection conflicts by default, including matching content.
Explicit takeover records the original selected unit, syntax and array position.
Every later update verifies the installed unit and keeps that first baseline.
Explicit adoption requires matching generated content and records a removal
rather than restoration disposition. Text adoption compares exact generated bytes;
structured adoption compares exact typed values, distinguishing booleans, integers,
floats and signed zero. Adoption also records the observed owned syntax.

Retirement removes intact created/adopted selections and restores intact takeovers.
Missing or modified selections retain ownership and their baseline. No artifact
label transfers a baseline to a different selector; retargeting requires retirement
and acquisition. Baselines contain only the selected unit, not a copy of unrelated
configuration. Structured baselines retain a syntax representation sufficient to
restore original native spelling, comments and scalar types.

The Python `SelectionSnapshot.layout` is immutable restoration metadata alongside
`value`, `syntax`, `owned_syntax` and optional `position`. Empty bytes mean no extra
layout data (including JSON, JSONC and text). Nonempty TOML layout is UTF-8 JSON:
`{"version":1,"headers":[[["env"],"mcp.test.env"]]}`. Each entry pairs a nonempty
path relative to the selected value with the original descendant table header
spelling, excluding brackets and comments. Path steps are object-key strings or
nonnegative integers within arrays contained in that owned value. These internal
offsets never select a member in a shared foreign array. Persist layout bytes
losslessly, using lowercase hexadecimal in a JSON receipt just as for other byte
fields.

The layout schema is closed: version must be the integer 1, field names cannot
repeat, and headers must contain unique relative paths. Each path must resolve to
an object in the snapshot. Header spelling must be exactly one TOML header path;
brackets, comments and newlines outside quoted key data are invalid. Quoted keys
may contain literal brackets and comment characters. Before applying layout,
the editor binds every header to the selected destination and relative path,
omitting array offsets from the TOML header name. Invalid layout is rejected.

Layout records only descendant headers inside the owned syntax. The selected
table's own header and its trailing gap are foreign and come from the live
document on replacement/restoration. TOML baseline syntax uses a synthetic
`value` root; the editor rebinds it to the actual destination before publication,
restores descendant header spelling, then verifies the entire reparsed document's
typed semantics. Installed snapshots describe that final reparsed syntax.

For JSONC and TOML, changes to formatting/comments *inside* an owned unit count as
modifications even when its typed value is unchanged. Key and surrounding container
trivia are foreign. JSON compares owned values semantically and permits whitespace
normalization of rewritten owned values. Foreign JSON values and map/array order
remain intact. The Python JSON editor currently preserves surrounding syntax too.
For an individual TOML array-of-tables member, its header comment and trailing
gap remain foreign, travel with the member when explicitly moved, and survive
removal as detached trivia. Selecting the whole array owns the headers between
its members; changes to those interior comments block replacement/restoration.

## Marked text

The selector is the actual start/end boundary pair. Marker labels are attribution.
Boundaries must be complete lines; inline occurrences, missing/reversed/repeated
boundaries and nested/intersecting selected spans are rejected. Standard Flyrail
markers in a document participate even if no current request selects them. Native
custom pairs participate when supplied by an existing claim or request. Unknown
custom conventions cannot be inferred from arbitrary prose.

The editor retains UTF-8 BOMs and surrounding bytes. Generated sections use the
existing opening boundary's LF, CRLF or CR newline convention; absent sections use
the document's first observed newline, defaulting to LF. Generated section body
line endings use that convention. Spaces and blank lines within the supplied body
are not trimmed. The closing marker includes its newline. An absent section is
appended, with only the newlines needed to separate it from existing content by a
blank line, using the document's first observed newline. Inserted separators are
owned conditionally: removal consumes them only while the exact separator remains
immediately adjacent to the intact owned section and outside every other recognized
section span. Expanded edit ranges must not overlap. User-added separating text or
different whitespace remains foreign.

## Structured selectors and array positions

A key step requires an object; a member step requires an array. Missing object
parents can be created as objects or arrays according to the next selector step.
Missing intermediate array members cannot be invented. Root arrays are supported
in JSON/JSONC; TOML has an object root. Numeric mutable indexes are never public
selectors. Native identity paths select scalar fields; exact identities select the
entire typed value. A member query rejects repeated identities under its identity
scheme, including repeated exact values. Foreign members without that native key
remain in place. Different identity schemes conservatively overlap.

A member payload must retain the selected identity. Without explicit placement,
an update keeps its current position. First/last placement and before/after unique
anchors can position acquisitions and updates. Missing, duplicate or self anchors
are conflicts. A takeover snapshots its immediate original previous/next members,
using their native keys when available and exact typed identities otherwise.
Inline arrays also retain the original trivia prefix within that anchored gap;
restoration after a move requires that prefix to remain intact. Insertion occurs
before a foreign member's leading trivia. This preserves its comment and spacing
when another member is inserted or moved.
Restoration requires surviving unambiguous anchors in their original relative
order. It inserts after a surviving previous anchor, otherwise before a surviving
next anchor. If neither survives, only an empty array gives a safe position.
Foreign additions retain their relative order; reversed surviving anchors block
restoration and retain the baseline.
When a batch retires multiple takeovers in one array, restoration plans their
original anchor dependencies together while retaining the current order of
foreign members. Request order cannot make jointly moved takeovers appear to be
a foreign reorder. Cyclic ordering constraints still block the complete batch.

JSONC accepts line/block comments and trailing commas. Duplicate keys, invalid
Unicode, unsupported JSON numbers and malformed syntax are errors. TOML uses its
native syntax and scalar types; unsupported selected nonfinite values are errors,
while unselected native nonfinite values remain untouched. Noncontiguous TOML
tables cannot be selected as one owned syntax unit; individual keys in their
contiguous tables remain selectable. Consecutive dotted-key fragments with the
same prefix spelling form one contiguous unit, including intervening comments;
a foreign key between fragments prevents aggregate selection. Adjacent
child-before-parent table declarations also form one owned unit; takeover and
restoration preserve their original header order and descendant spelling.
Contiguity follows physical table and key order, including when an enclosing
parent is declared later. TOML arrays and arrays of tables support
stable member selection. An existing TOML header table or array of tables cannot
be changed into another representation: that would move native keys and lose
their original layout on restoration. Updates within the same representation,
including MCP table objects and hook members, are supported. An existing scalar
or inline value can become an object using an inline table, retaining its key's
position and syntax. JSON cannot render TOML date/time values; TOML cannot
render null. Such requests conflict without changing the document.

## Creation provenance

Created document and container evidence belongs to the resource and survives the
retirement of the first creating claim while other claims remain. A container is
removed only when it is empty, has its original created empty syntax, and has no
remaining overlapping claim. Empty containers that existed before acquisition are
foreign. Added comments or whitespace prevent pruning. A document created from
absence is removed only when its content returns exactly to its created empty
representation after pruning. An inserted TOML EOF separator can be removed only
when removing it returns to the hashed original foreign revision.

When every claim has retired, any document/container retained because of foreign
content becomes fully user-owned and its creation evidence is relinquished. A
later acquisition starts with that foreign document; old evidence cannot make it
disposable. Filesystem parent-directory provenance belongs to the lifecycle layer.

`fixtures/edits.json` contains portable sequential edit vectors and invalid-input
vectors. Each sequence supplies its complete original document, requests, optional
foreign observed revisions, expected complete output and expected disposition or
conflict. The consumer carries the production editor's ownership/provenance through
every step, verifies first-baseline continuity, and checks that blocked operations
retain the original ownership and provenance. These fixtures complement the
receipt/recovery vectors in `configurations.json`.
